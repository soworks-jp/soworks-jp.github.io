## Public signup, private-sensitive follow-up

The product repositories are still private while public OSS release gates are being finalized. The signup issue therefore lives in this public Pages repository so anyone can opt in. After the initial opt-in, sensitive coordination can move to a private channel when needed.

## What not to share

Do not put source code, raw prompts, secrets, customer data, private repository identifiers, sensitive personal memories, local paths, or raw logs into the public waitlist issue. Share only the minimum workflow description needed to establish fit. Pilot evidence should be sanitized and aggregate-only.

## How we use pilot evidence

We prioritize completed experiments over sign-ups. A pilot should answer a product question such as:

- Did the user reach a useful outcome quickly enough?
- Did they return for a second or third use?
- Which stage caused the first drop-off?
- Which recommendation was wrong or unsafe?
- Did a review produce incremental signal worth the extra time?
- Did memory remain understandable and controllable when it was wrong?

The next feature should be chosen from repeated evidence, not from the longest feature wish list.
